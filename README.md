# LifeQuest

Геймификация жизни: квесты, сферы развития, здоровье и прогрессия персонажа.

## Как запустить

Нужен Node.js 18 или новее.

Веб-интерфейс:

```bash
cd web
npm install
npm run dev
```
Откройте адрес из терминала (обычно http://localhost:5173). Чтобы увидеть телефонный вид, нажмите F12 и включите режим устройства.

## Запуск тестов

```bash
npm install
npm test        # разовый прогон
npm run watch   # следить за изменениями
```

167 тестов в восьми файлах, включая проверку SQL. Запускаются без установки Postgres.
CI прогоняет их на каждый push и отдельно применяет схему к Postgres 16.

## Где живёт логика

Математика геймификации намеренно продублирована: `lib/gamification.ts`
даёт мгновенный отклик интерфейсу, а SQL-функции в `schema.sql` — источник
истины, который клиент не может обойти. Начисление XP идёт через триггер
Postgres, поэтому подделать запрос и накрутить себе опыт невозможно.

Риск расхождения этих двух реализаций закрыт тестом `sql-drift.test.ts`:
он парсит `schema.sql` и сверяет каждую константу с TypeScript.

## Ключевые решения баланса

**Кривая уровней** `xp = 100 · n^1.538`. Прирост за уровень растёт, но
выполаживается: на сотом уровне один уровень стоит 1 800 XP, а не 4 100,
как давала бы квадратичная формула. Калибровка проверена на реальных
данных: 4 040 XP дают уровень 11.

**Множители складываются, а не перемножаются.** Серия 30 дней плюс фокус
плюс утро дают ×1.8, а не ×2.64. Суммарная надбавка ограничена потолком ×2.5.

**Дневной потолок.** До 300 сырых XP начисление полное, до 500 — половина,
дальше — четверть. Обычный день из семи квестов даёт около 170 сырых XP,
поэтому потолок ловит накрутку, а не честную игру.

**Стрики не обнуляются.** Две заморозки в месяц, а когда они кончились —
серия падает на три дня, а не в ноль. Один пропуск не должен стирать месяц работы.

## Статус проекта

| Часть | Статус |
|-------|--------|
| Математика уровней, бонусов, потолка, стриков | Тесты, включая мутационную проверку |
| Симуляция месяца игры | Тест темпа прогрессии |
| `schema.sql` на Postgres | Выполняется на Postgres (PGlite) в тестах и на Postgres 16 в CI |
| SQL-функции против TypeScript | `tests/sql-parity.test.ts`: одинаковые входы, сверка результатов |
| Триггер начисления XP | Тест целиком: профиль, сфера, daily_stats, потолок, монеты, RLS-инварианты |
| Импорт здоровья | Логика и тесты; нативные обёртки HealthKit / Health Connect не написаны |
| База продуктов | Open Food Facts; сетевые тесты используют подмену fetch |
| Экспорт в Obsidian | Генерация и запись протестированы; выбор папки в приложении не реализован |
| Прототип интерфейса | Демонстрационный, на моковых данных, без тестов |

Схема рассчитана на Supabase: таблицы ссылаются на `auth.users`, а RLS
использует `auth.uid()`. В тестах эти объекты создаются заглушками из
`tests/sql/supabase-stubs.sql`.
